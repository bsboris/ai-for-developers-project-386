# TimeSpot — Domain Model

## 1. Owner (CalendarOwner)

Единственный предопределённый владелец календаря.

| Поле | Тип | Описание |
|---|---|---|
| `id` | `string` | Фиксированный идентификатор (например, `"owner"`) |
| `name` | `string` | Имя владельца |
| `email` | `string` | Email для уведомлений (опционально) |

В проекте не предполагается регистрация или создание новых владельцев. Профиль жёстко задан (в коде, `.env` или БД при инициализации). Доступ к админ-панели — через Basic Auth (логин/пароль из конфигурации).

---

## 2. EventType (Тип события)

Тип встречи, который создаёт владелец. Определяет длительность и доступное время для бронирования.

| Поле | Тип | Описание |
|---|---|---|
| `id` | `string` | Уникальный идентификатор (slug, например `"consultation"`) |
| `name` | `string` | Название типа события |
| `description` | `text` | Описание для гостя |
| `duration` | `integer` | Длительность в минутах |
| `availability` | `Availability[]` | Рабочие часы для этого типа (по умолчанию будни 9:00–18:00) |
| `createdAt` | `datetime` | Дата создания |
| `updatedAt` | `datetime` | Дата последнего изменения |

### Availability (Рабочие часы типа события)

| Поле | Тип | Описание |
|---|---|---|
| `dayOfWeek` | `integer` | День недели (0 — воскресенье, 6 — суббота) |
| `startTime` | `time` | Начало рабочего окна (например, `"09:00"`) |
| `endTime` | `time` | Конец рабочего окна (например, `"18:00"`) |

Для каждого типа события можно задать несколько диапазонов на разные дни недели. Все дни, не указанные в `availability`, считаются нерабочими.

---

## 3. Slot (Слот)

**Виртуальная сущность** — не хранится в БД, а вычисляется на лету.

Слот — это свободный временной интервал, доступный для бронирования конкретного типа события.

### Алгоритм вычисления

```
рабочие часы EventType.availability
  − заблокированные интервалы (BlockedInterval)
  − уже занятые слоты (подтверждённые Booking)
  − шаг = длительность события
= список доступных Slot
```

| Поле | Тип | Описание |
|---|---|---|
| `startTime` | `datetime` | Начало слота |
| `endTime` | `datetime` | Конец слота (= startTime + duration типа события) |
| `eventTypeId` | `string` | Тип события, для которого сформирован слот |

**Ограничения:**
- Слоты формируются в окне 14 дней с текущей даты
- Шаг сетки равен длительности типа события
- Пересекающиеся слоты не допускаются (даже для разных типов событий)
- Время вне рабочих часов, заблокированные дни и занятые интервалы исключаются

---

## 4. Booking (Бронирование)

Запись о подтверждённой встрече гостя.

| Поле | Тип | Описание |
|---|---|---|
| `id` | `string` | Уникальный идентификатор (UUID) |
| `eventTypeId` | `string` | Тип события (ссылка на EventType) |
| `startTime` | `datetime` | Начало встречи |
| `endTime` | `datetime` | Конец встречи |
| `guestName` | `string` | Имя гостя |
| `guestEmail` | `string` | Email гостя |
| `comment` | `text` | Комментарий гостя (опционально) |
| `status` | `enum` | `confirmed` или `cancelled` |
| `cancellationToken` | `string` | Секретный токен для отмены гостем (UUID) |
| `createdAt` | `datetime` | Дата создания |
| `updatedAt` | `datetime` | Дата обновления (например, при отмене) |

**Правила:**
- `startTime` и `endTime` не пересекаются с другими Booking (даже других EventType)
- При отмене статус меняется на `cancelled`, запись не удаляется
- Ссылка на отмену содержит `cancellationToken` (без авторизации)

---

## 5. BlockedInterval (Заблокированный интервал)

Интервал времени, который владелец вручную пометил как недоступный.

| Поле | Тип | Описание |
|---|---|---|
| `id` | `string` | Уникальный идентификатор |
| `startTime` | `datetime` | Начало блокировки |
| `endTime` | `datetime` | Конец блокировки |
| `reason` | `text` | Причина (опционально, для владельца) |
| `createdAt` | `datetime` | Дата создания |

Блокировки имеют приоритет над рабочими часами — слоты внутри блокировки не формируются.

---

## 6. Публичный сценарий гостя

```
  Шаг 1   →  GET  /                         — список типов событий
  Шаг 2   →  GET  /book/{eventTypeId}       — страница выбора времени
  Шаг 3   →  GET  /api/slots?eventTypeId=X&date=YYYY-MM-DD&timezone=Europe/Moscow
                                              — получение свободных слотов на дату
  Шаг 4   →  POST /api/bookings             — создание бронирования
              { eventTypeId, startTime, guestName, guestEmail, comment? }
  Шаг 5   →  отображается страница подтверждения
              с ссылкой для отмены: /cancel/{bookingId}?token={cancellationToken}
```

### Схема данных для POST /api/bookings

```json
{
  "eventTypeId": "consultation",
  "startTime": "2026-06-10T10:00:00Z",
  "guestName": "Иван Петров",
  "guestEmail": "ivan@example.com",
  "comment": "Хочу обсудить проект"
}
```

### Отмена бронирования (гость)

```
  GET  /cancel/{bookingId}?token={token}
```

- Если `bookingId` и `token` совпадают → статус меняется на `cancelled`
- Если не совпадают → ошибка 404
- Повторная отмена → ошибка (бронирование уже отменено или не найдено)

## Сводная ER-диаграмма (текстовая)

```
Owner (1) ──< EventType (N)         — владелец создаёт типы событий
EventType (1) ──< Booking (N)       — тип события имеет бронирования
Booking (N) ───> Slot (виртуальный) — бронирование занимает слот
Owner (1) ──< BlockedInterval (N)   — владелец блокирует интервалы
```

`Slot` — виртуальная сущность, вычисляется на основе EventType.availability, BlockedInterval и существующих Booking.
